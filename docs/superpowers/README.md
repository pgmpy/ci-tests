# Design specs

Records of *why* the library is shaped the way it is: the options considered,
the decisions taken, and the evidence behind them. They are historical
documents — a spec describes the state of the world when it was written, not
necessarily the state now — so read them for rationale, not as a description of
current behaviour. The code, its tests, and the root `README.md` are the
authority on what the library does today.

The step-by-step implementation plans that accompanied these specs are not
kept. They were execution checklists, consumed once, and referred to files and
package names that no longer exist; a contributor following one would be
actively misled. They remain in git history.
